🚀 Order Management System: High-Availability Microservices
Современная экосистема управления заказами, построенная на принципах EDA (Event-Driven Architecture) и гарантированной доставки данных. Это не просто CRUD-приложение, а отказоустойчивая система, готовая к нагрузкам и сложным сценариям сетевых сбоев.

🛠 Технологический стек
Core: Java 21, Spring Boot 3.x, Gradle.

Data Consistency: PostgreSQL, Hibernate.

Messaging: Apache Kafka, Debezium (CDC).

Communication: gRPC (межсервисное взаимодействие с высокой пропускной способностью).

Observability: OpenTelemetry & Micrometer Tracing (для сквозного мониторинга запросов).

🏗 Архитектурные особенности
Проект реализует продвинутые паттерны проектирования, которые выделяют его на фоне типовых решений:

Transactional Outbox Pattern: Использование Debezium для захвата изменений из БД и гарантированной отправки событий в Kafka. Это исключает потерю данных при сбоях брокера сообщений.

Idempotent Consumer (Inbox Pattern): Внедрена строгая проверка входящих событий в сервисе уведомлений. Каждое техническое событие обрабатывается ровно один раз, что предотвращает дублирование действий при повторных попытках доставки.

Distributed Tracing: Интеграция Trace ID во все события позволяет отслеживать путь заказа «от и до» сквозь все микросервисы в едином логе.

gRPC Integration: Использование протоколов Google Protocol Buffers для типизированного и быстрого общения между сервисом заказов и инвентаризацией.

🧩 Ключевые сервисы
Order Service: Сердце системы. Управляет жизненным циклом заказа, координирует проверки через gRPC и фиксирует события в Outbox.

Inventory Service: Обрабатывает резервирование товаров и передает актуальный статус наличия.

Notification Service: Асинхронно реагирует на изменения статусов, обеспечивая идемпотентную обработку бизнес-событий.

Common Lib: Общая библиотека с моделями событий, перечислениями и утилитами для трассировки, обеспечивающая DRY-подход.

Почему это решение заслуживает внимания?
Приложение решает классическую проблему Dual Write, обеспечивая атомарность записи в базу данных и отправки сообщения в очередь. Архитектура спроектирована так, чтобы система оставалась консистентной даже в условиях нестабильной сети или временного падения отдельных узлов.
